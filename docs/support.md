# CallTrace v0.1 支持范围

CallTrace 提取静态结构，输出从指定入口可见的有界调用图与时序 IR。它不运行目标源码、不执行项目构建，也不调用 LLM 决定函数之间是否有边。以下说明区分“语法被解析”和“目标被可靠绑定”。

## 语言矩阵

| 语言 | 扩展名 | 当前解析/绑定范围 | 主要边界 |
| --- | --- | --- | --- |
| Python | `.py` | 函数、方法、词法嵌套；同文件和项目内显式模块/符号导入；部分相对导入；静态方法和可确定的局部对象 | `self`/`cls` 不作为确定类型；动态导入、星号导入、运行时装饰/替换和任意回调传播不作完整推断；必须是 UTF-8 源文件 |
| JavaScript | `.js`、`.mjs`、`.jsx` | 函数、方法、箭头/函数表达式；相对路径显式 ES module 导入、具名导出列表与显式重导出；局部具体接收者 | 不提供 Node 包解析、CommonJS、bundler alias、星号重导出或完整重导出语义；`this`、动态属性和参数回调保守未解析；JSX 语法不等于组件调用图 |
| TypeScript | `.ts`、`.tsx` | 与 JavaScript 相同的结构与有限 ES module 绑定 | 不运行 TypeScript 类型检查，不解析 `tsconfig` 路径映射、泛型/联合类型分派；TSX 与类型声明不保证调用可解析 |
| Java | `.java` | 方法与带签名的符号；同包静态调用、显式类/静态导入和具体局部实例 | 重载保留候选集合，未做实参类型选择；继承、接口、反射和 `this` 分派不作完整推断；构造器调用不展开 |
| Go | `.go` | 函数、接收者方法；同目录同包调用；项目根 `go.mod` 下的本模块显式导入；具体局部值和接收者 | 不加载外部模块，不处理完整 `replace`/workspace/build tag 语义，不推断接口动态类型；`go` 仅标记并发，`defer` 保留未解析及延迟标记 |

五种语言使用独立 Tree-sitter grammar。语言支持不是编译器等价承诺；同一语言中未列明的特性可能只被结构遍历，不能从一张没有报错的图推断语义完整。

## 符号和解析规则

先提取定义与调用点，再执行作用域和有限导入绑定。没有全项目同名兜底。外部依赖即使与项目内函数同名，也不能仅凭名字绑定。

| 状态 | 含义 | 展开行为 |
| --- | --- | --- |
| `exact` | 当前支持的静态规则得到唯一目标 | 在深度范围内展开，遇当前路径递归停止 |
| `unresolved` | 目标外部、类型未知、受遮蔽、动态/延迟执行或有多个候选等 | 保留表达式、位置、原因和候选，不展开 |
| `heuristic` | IR 保留的非确定状态；当前正常解析流程不主动生成启发式猜测边 | 渲染时保留状态，绝不递归展开 |

`confidence=1.0` 是 `exact` 的规则标记，不是经统计校准的正确概率。`exact` 不证明运行时类型、猴子补丁、反射、动态加载或框架注入后的真实行为。

有限局部接收者绑定不等于全程序数据流分析。参数、重赋值和不明确接收者必须谨慎处理；不能根据同类方法名称把 `self.foo()`、`this.foo()` 或 `provider.foo()` 自动补成边。构造对象可能帮助识别后续方法的局部类型，但不会生成隐式 `__init__` 或构造器内部调用链。

入口接受唯一短名、限定名、`相对文件::限定名`、模块限定名或完整 symbol ID。多个候选时返回退出码 `2` 并列出 ID，不取第一项。Java 同名重载调用保留候选，不因某个实参看似匹配就选择它。

普通符号 ID 由相对文件、限定名组成，Java 额外包含签名；匿名函数和重名冲突使用位置消歧，因此编辑行列位置会改变这些 ID。调用点 ID 也依赖位置。ID 对相同源码和项目相对布局稳定，不承诺跨重构永久稳定。

## 时序含义

`sequence.json` 是 Mermaid 的唯一渲染输入，渲染器不再次读取源码。符号与调用证据在 `callgraph.json`，两者通过 symbol ID 和 `call_id` 关联。

- 入口深度为 `0`。深度 `1` 展示入口体直接调用；每展开一条调用边消耗一层，分支/循环块不消耗深度。
- 接收者和实参中的调用先于外层调用，例如 `f(g())` 先表示 `g()` 再表示 `f(g())`。这是受支持语法下的结构顺序，不是采样到的运行事件。
- 条件与分支用 `alt`，循环用 `loop`，短路和提前退出后的继续条件用 `opt`。不会计算条件真假、迭代次数或执行可达性。
- `await` 表示等待上下文；Go 的 `go` 调用带 `async` 标记。图不证明并发先后、任务完成顺序或线程关系。
- Go `defer` 当前超出执行时序模型，保留 `deferred` 和 `unresolved`，不伪装成当场执行的展开调用。
- 递归按当前展开路径检测，显示回边和停止说明。不同调用点对同一函数的重复调用仍展示；调用图按唯一调用点记录，不按展开次数重复计数。
- 深度达到上限时，仍保留到达目标的边，并在目标有可展开体时标记 `depth limit`。增加深度不能修复未解析绑定。
- `return`、`raise`、`throw`、`break`、`continue` 用说明节点表达；不会编造返回值或运行时返回箭头。

不提供完整 CFG、异常传播、`try/finally`、模式匹配、生成器恢复、异步调度或框架生命周期建模。模块顶层执行也不等同于可选函数入口；闭包可以被提取为符号，但把闭包传给其它函数不证明何时、是否会被调用。

## 证据与完整性

调用记录保留 `file`、`line`、`column`、结束位置、源码 `expression`、调用者/被调用者、`order`、`context`、`rule`、`reason`、`candidates` 和 `resolution`。位置使用从 1 开始的行号与列号；Tree-sitter 列是 UTF-8 字节列，含中文时不要当作字符列。

文件路径相对分析根，使用 `/` 分隔，不把机器绝对根写入正常符号路径。路径支持 Unicode；Mermaid 的内部参与者 ID 则是 `p0`、`p1` 等 ASCII 标识。源码标签被转义后写入 Mermaid，不能当作额外图语法。

所有源码都按 UTF-8 解码，包括 Python。非 UTF-8 文件、读取失败和 Tree-sitter 错误节点进入项目诊断。一个不在入口展开路径上的坏文件也能使报告标记 `incomplete`、CLI 返回 `1`。仍存在可选入口时可能生成部分产物；入口本身不存在时会返回入口错误。

`callgraph.json` 和 `unresolved.json` 的调用范围限于这次入口/深度可见的调用点，而 `diagnostics` 是项目扫描级别。`unresolved.json` 为空不证明整个项目无盲区；退出码 `0` 也不证明图完整覆盖所有运行行为。报告中的 `complete (within documented static model)` 只表示没有项目诊断。

## 文件扫描和安全边界

扫描仅识别矩阵中的扩展名，不跟随目录或文件符号链接。默认排除 `.git`、`.hg`、`.svn`、`.venv`、`venv`、`env`、`node_modules`、`vendor`、`dist`、`build`、`target`、`.cache`、`.calltrace`、`__pycache__`、`.pytest_cache`、`.tox`。显式输出目录在遍历中跳过。

当前不读取 `.gitignore` 作为通用扫描规则，也没有文件大小限制、完整 generated-code 检测或依赖安装流程。大型项目应选择适当分析根，保持所需跨文件模块位于该边界内。

CLI 读取目标源码并写图产物，不执行目标程序、不导入其模块、不运行项目钩子或构建命令。没有运行时录制、网络服务、自动上传、自动全局 skill 安装。已有输出目录中的五个同名产物会被覆盖；I/O 失败可能留下部分产物，应以本次退出码和报告判断，不能把旧文件当成本次成功结果。

## 验证范围

仓库中的 Python 示例可生成带源码证据的时序图。运行 `calltrace sequence examples/python --entry UserService.login --depth 4`，再运行 `npm run validate:mermaid` 校验 Mermaid 语法。详细环境命令见 [README](../README.md#示例与构建)。

语法校验只证明图能解析，不能证明调用关系真实。新增语言特性需要同时验证正确绑定与不会产生错误 `exact` 边。
